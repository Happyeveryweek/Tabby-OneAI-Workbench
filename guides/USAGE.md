## 一、快速上手流程

### 1. 添加项目（支持 Windows 与多 WSL 发行版）
- **核心组织逻辑（`项目 → AI CLI → 会话`）**：工作台以「项目」为基准 -- 一个项目下可以同时使用多个 AI CLI 协作编码，每个 AI CLI 下又可以并行或留存多条独立会话。
- 点击左侧工作台底部的 **「+ 添加项目」**，选择运行环境（`PowerShell 7` 或任意已安装的 `WSL` 发行版），选择或输入项目目录路径。
- **自动扫描并导入历史会话**：手动添加项目目录后，无需任何手动导入操作，插件会**自动扫描并归集该目录下所有已支持 AI CLI 留存的历史会话**，立即按 CLI 分组展示在项目树中（同时显示 Git 分支与 `WIN` / `WSL` 环境徽章）。
- 点击项目右侧的 **图钉图标** 可将常用项目永久置顶；右键项目支持 **新建会话**、**查找历史会话…**、**打开项目文件夹**（自动映射 WSL `\\wsl.localhost\...` 路径）与 **查看项目全部用量**。

### 2. 启动新会话与恢复历史会话
- **新建会话**：右键项目 → 「打开新会话」，仅显示当前项目环境实际已安装的 AI CLI；发送第一条消息落盘后，左侧会话标题、右侧提示词抽屉与 Token 统计会自动实时绑定。
- **恢复历史会话**：双击左侧任意历史会话，立即在原生 Tabby 标签页中按原目录、原环境变量与原会话 ID 精准续聊；如果该会话已在某个标签页中打开，双击直接聚焦过去，不会重复启动。
- **折叠与展开**：每个 CLI 分组默认显示最近 `2` 条会话，点击「更多会话…」按 `+3` 步进展开，也可随时点击「收起会话」。

### 3. 看懂五种运行状态与「新输出」提醒
所有状态在 **顶部标签底条**、**会话状态栏**、**侧栏 CLI 分组胶囊** 与 **会话圆点** 四处保持严格一致：

| 状态 | 颜色 | 含义 |
| :--- | :---: | :--- |
| **`Running`** | 翡翠绿 | AI 正在思考、调用工具或运行后台子任务；标签底条呈现柔和同色呼吸动效 |
| **`Waiting`** | 琥珀金 | AI 暂停并等待你确认权限或执行审批（如 `Allow once`、`[y/n]`） |
| **`Ready`** | 青蓝色 | 会话在线并停在空闲提示符，随时可输入下一轮指令 |
| **`Error`** | 珊瑚红 | 本轮对话因 API / 限额 / 认证报错最终停止（自动重试期间仍保持 `Running` 不误报红） |
| **`Exited`** | 空心灰环 | 历史离线会话（双击可一键恢复） |

- **「新输出」提醒**：仅当后台未聚焦的 AI 会话实际执行了新任务或进入等待审批时，侧栏对应会话行才会亮起琥珀色 `新输出` 微标；切过去看完即自动消除。
- **运行中防误关保护**：当会话处于 `Running` / `Waiting` 时，误点关闭标签页或退出 Tabby 窗口会弹出二次确认框，防止中止长耗时任务。

### 4. 状态栏、用量统计大盘与历史提示词抽屉
- **顶部动态状态栏**：仅渲染当前 CLI 实际支持且存在有效数据的胶囊（`Tokens`、`5h / 7d` 剩余额度与倒计时、`Model / Effort`、`Ctx` 三色上下文水位条）；Codex 支持点击刷新图标手动拉取最新在线额度。
- **用量统计大盘**：点击状态栏 `Tokens` 或统计图标打开，支持 **项目 → 会话 → 模型** 三级级联筛选，近 12 个月展示 52 周热力图，本月/本周切换为每日柱状图，悬停分布条或模型行可查看输入 / 缓存读取 / 输出拆分。
- **历史提示词抽屉**：点击状态栏时钟图标（或按 `Ctrl-Alt-Shift-H`）从右侧滑出，倒序展示当前会话的所有历史 Prompt，支持搜索过滤、展开长文本与一键复制。

### 5. 多账号数据目录、外观主题与快捷键
点击侧栏右下角 **齿轮图标**（或按 `Ctrl-Alt-Shift-O`）打开「工作台设置」：
- **外观**：独立切换「简体中文 / English」、调整字号、搜索切换本机任意字体、切换 16 套内置护眼与编辑器主题。
- **CLI 环境与目录**：为 `Codex`、`Claude Code`、`Pi`、`Kimi Code`、`Grok Build`、`GitHub Copilot` 配置多个数据目录 / 多账号，并指定默认启动目录，实时显示路径是否存在。
- **CLI 检测**：按 `PowerShell 7` 或各 `WSL` 发行版一键重检 PATH 中的可用 CLI。
- **会话管理**：找回此前从工作台移除的会话，按项目折叠分组，支持单条或按组一键全部恢复。
- **快捷键**：点击直接录制新快捷键，支持冲突检测与一键恢复推荐键位：

| 功能动作 | 默认推荐快捷键 |
| :--- | :--- |
| 折叠 / 展开左侧项目工作台 | `Ctrl-Alt-Shift-B` |
| 打开当前会话 / 项目用量统计 | `Ctrl-Alt-Shift-U` |
| 打开 / 关闭历史提示词抽屉 | `Ctrl-Alt-Shift-H` |
| 打开工作台设置 | `Ctrl-Alt-Shift-O` |

## 二、常见问题与注意事项 (FAQ)

### Q1：重启 Tabby 后，为什么之前开着的 AI 会话没有自动恢复？
自动恢复依赖 Tabby 原生的标签恢复机制，请检查是否已开启：
- **操作路径**：Tabby 右上角 **齿轮（设置）** → **应用程序（Application）** → 开启 **「启动时恢复上次的标签页（Recover tabs on startup）」**。
- 开启后，下次重启 Tabby 时，原来打开的 Windows 与 WSL AI 会话标签页都会自动恢复，并自动重新关联状态栏与侧栏状态。

### Q2：在 Tabby 里修改了「默认启动终端」（比如改成了 WSL 或 PowerShell），会影响另一边环境的会话恢复吗？
**完全不会。** 每个项目在加入工作台时就已绑定自己的运行环境，启动和恢复会话时插件都会显式调用 `pwsh.exe`（Windows 项目）或 `wsl.exe --distribution <distro>`（WSL 项目），与 Tabby 的默认启动终端互不干扰。

### Q3：为什么我明明装了某个 AI CLI，但右键项目启动菜单里看不到它？
1. **检查安装环境是否一致**：插件严格隔离 Windows 与 WSL 环境（在 WSL 项目中会自动忽略宿主机挂载的 `/mnt/*` 路径以及 VS Code 的 `copilot-shim` 占位桩）。在 Windows 安装的 CLI 不会出现在 WSL 项目的菜单里，反之亦然。
2. **手动触发重新检测**：如果你是在打开 Tabby 之后才新安装的 CLI，打开 **工作台设置 → CLI 检测**，选择对应环境点击 **「重新检测」** 即可刷新缓存。

### Q4：在终端里按 `Ctrl+C`、`Esc` 或输入 `/exit` 退出 CLI 后，标签页直接关掉了，对话记录会丢吗？
**不会丢失。** 退出 CLI 时自动关闭空闲壳标签页是为了避免残留一堆无用黑窗；你的完整对话记录已经保存在本地 CLI 日志中，侧栏会话状态会变为 `Exited`，随时双击即可按原会话 ID 恢复继续聊。

### Q5：在侧栏点击「从工作台移除会话 / 移除项目」会删掉本地记录吗？
**绝对不会。** 「移除」仅是在工作台侧栏隐藏该条目，不会删除任何本地 CLI 日志文件或项目源码；随时可以在 **工作台设置 → 会话管理** 中按项目找回并一键恢复。

### Q6：AI CLI 提示有新版本，我在会话里选了 `Update now` 或执行 `/update` 会怎样？
插件内置了全 CLI 自更新保护：检测到你在执行更新后，会自动把状态切为 `Running` 并锁定当前标签页不关闭；**更新成功后会在当前标签页原地自动拉起新版本 CLI 并恢复原会话**；如果更新报错则会保留终端画面方便排查。

### Q7：为什么 Antigravity (`agy`) 或 Claude Code 状态栏没有显示实时指标？
这两个 CLI 的实时状态栏桥接脚本依赖对应运行环境中的 `node` 命令。请确认你对应的 Windows 或 WSL 环境中可以直接运行 `node -v`。

### Q8：用量统计大盘的 Token 数据和官方后台账单完全一致吗？
统计大盘是基于本机 / WSL 中各 CLI 落盘的会话日志只读解析汇总而成，部分 CLI 日志不含极早期的元数据或缓存计费系数，因此数据**仅供参考**，实际计费请以各服务商官方后台为准。

## 三、隐私与安全说明

- **100% 本地只读解析**：所有历史会话、提示词与 Token 统计均在本地直接读取，插件不设立任何后端服务器，不上传任何代码、对话或统计数据。
- **零凭据触碰**：API Key、OAuth Token 与登录态完全由各 AI CLI 自行管理；插件不读取也不写入任何密钥或终端正文到外部文件与日志。
- **配置本地隔离**：项目列表、外观主题与自定义数据目录仅保存在当前 Tabby 实例的本地 `localStorage` 中。
